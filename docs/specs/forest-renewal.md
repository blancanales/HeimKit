# ForestRenewal specification

## Behavior and mappings

Observe existing/new eligible stumps and accepted native stump destruction. Both routes share one persisted chance decision and timer per original stump ID. When eligible, replace the standing stump or renew its confirmed-cleared position with one vanilla sapling. Removing a previously observed stump preserves its pending decision rather than cancelling or rerolling it. Missing/unloaded records alone never count as destruction. Runtime mapping checks join Plant.m_grownPrefabs to TreeBase.m_stubPrefab in installed prefabs, with exactly one matching requested sapling per stump.

| Stump | Sapling | Native grown tree |
| --- | --- | --- |
| Beech_Stub | Beech_Sapling | Beech1 |
| BirchStub | Birch_Sapling | Birch1 / Birch2 |
| OakStub | Oak_Sapling | Oak1 |
| FirTree_Stub | FirTree_Sapling | FirTree |
| Pinetree_01_Stub | PineTree_Sapling | Pinetree_01 |
| FirTree_Big_plantable_Stub | FirTree_big_Sapling | FirTree_big |

Snow variants, ancient/swamp trees, Yggdrasil, Ashlands trees, decorative stumps and ambiguous/missing mappings are excluded. The [Treesurrection reference](https://github.com/ArgusMagnus/ValheimServersideQoL/blob/main/ServersideQoL.Treesurrection/StumpProcessor.cs) maps these native components but changes plant growth fields. HeimKit leaves every native growth requirement intact, including biome, space, sunlight and plant failure behavior.

## Configuration and defaults

ForestRenewal.Enabled=true enables supported tree renewal by default; DebugMode=false. DelaySeconds=300 (10..86400) starts at first observed standing stump or confirmed removal and avoids immediate replacement; old stumps receive a fresh full delay when first discovered. ChancePercent=50 (0..100) limits automatic replenishment. StructureExclusionMeters=10 (0..50) rejects locations within that horizontal distance of the conservative saved collision footprint of any nonzero-creator Piece; zero disables this exclusion. Include rotated/scaled box, sphere, capsule and mesh bounds, including inactive variants, with the piece pivot retained in the bound. Walls, floors, beams, workbenches and other player-built pieces qualify. Missing/unsupported geometry or nonfinite/excessive scale defers renewal rather than guessing. Check immediately before stump replacement/sapling placement, so structures built during the delay are included. Existing mature trees are not removed. ExcludeClearedGround=true rejects all native dirt, paved and cultivated paint, conservatively including detectable roads. Unpainted travel routes cannot be identified. ExclusionRadiusMeters=3 (0..10) samples terrain paint on a one-metre grid. LocationCooldownHours=24 (1..720) limits repeated stump harvesting in a five-metre horizontal area. IntervalSeconds=2 (1..30), ScanRangeMeters=64 (16..128) bound actor-relative processing. MaxPending=1024 (1..4096) bounds pending events; the ledger has a hard 16,384-record cap and stops accepting events at capacity. Failed chance rolls are recorded once per original stump; they are never rerolled.

## Persistence and processing

Discover up to thirty-two previously unseen supported standing stumps per rotating player scope and queue their decisions in one immutable snapshot per pass. Serialize snapshots on the main thread; checksum and durable atomic file I/O run on one background task at a time. Background work touches no game objects. Poll completion on the main thread and propagate write failures before any dependent world mutation. Dirty generations arriving during a write wait for the next snapshot. Observe ZDOMan.m_onZDODestroyed only while occupied for confirmed removed stumps. Accept at most 32 previously unseen removals per processing interval; tracked pending stumps still receive their state transition. Batch non-placement ledger writes at processing boundaries. A pending placement records its required snapshot generation and cannot mutate the world until that generation is durably acknowledged. Recheck source identity and all current placement exclusions after acknowledgement. If context stays unavailable for sixty seconds before world mutation, return the same decision to its original pending state without rerolling, releasing the pipeline for later candidates. A new attempt requires a new durable generation. Once world mutation starts, consumed state cannot be rolled back or replayed. Confirmed stump destruction during the write wait changes only the pending source reference, preserving that same decision; missing records alone do not. Orderly pause/shutdown returns unperformed placements to their original pending state, waits for the existing write and flushes remaining dirty state. An attempted world mutation remains consumed. Both routes deduplicate by source ID and share the same chance roll/timer. A tracked standing stump becoming absent without a destruction event waits; absence alone cannot authorize renewal. Confirmed destruction changes a pending standing decision to a pending removed decision without rerolling or resetting its timer. Existing pending removed entries remain compatible if their source stump is present in a restored world.

The checksummed, atomic world-UID ledger lives under the loader config directory at HeimKit/ForestRenewal. Format two preserves the existing record layout and reads format-one removed-stump decisions without rerolling. It adds an explicit pending-standing state; source absence never silently changes that state. Corrupt, missing-with-backup or incompatible data disables this module rather than resetting it. Native world time controls delay; pending decisions survive pause/restart.

Examine at most one due candidate per pass and retain at most one consumed placement awaiting durable acknowledgement. Check the structure exclusion before requesting terrain preparation. A later pass performs the acknowledged placement only after fresh context checks; preparing one cannot also prepare another in the same pass. Require synchronized terrain, reliable current structure/geometry records, no other nearby Plant/TreeBase/stump and safe dry native ground. Protect every existing Plant regardless of creator or health, including player-planted tree saplings and crops. PlantExclusionMeters defaults to 10 (10..50), independently of StructureExclusionMeters. Its horizontal exclusion distance is at least PlantExclusionMeters and at least the larger native growth radius of the proposed sapling and existing plant, adjusted conservatively for existing replicated scale. Check immediately before replacement/placement, so planting during the waiting period also prevents renewal. Nonfinite/unsupported plant state postpones renewal. A blocked standing stump remains intact; no existing plant is removed. The source stump itself is excluded from the obstruction scan. Unsupported/missing context defers processing; confirmed terrain, building and cooldown exclusions consume the decision. Structure and terrain exclusions apply identically to both renewal routes.

Before standing-stump conversion, acquire a short shared server ownership/data/destruction fence. Require durable acknowledgement of the consumed decision first. Send the native DestroyZDO message through the server's native routed dispatcher, confirming synchronous server record removal before creating a sapling; this uses the same native record-deletion path as ZDOMan.SendDestroyed and bypasses Destructible's chopping effects/loot. Release only this feature's retained ID afterward. Removed-stump renewal needs no source deletion. In both cases create the ordinary persistent vanilla sapling and native plant timestamp, leaving all native growth fields unchanged. Native world saving owns sapling persistence. At-most-once ledger consumption prevents repeated creation; a crash/failure between consumption and world saving can forfeit that renewal. No replay restores a consumed opportunity.

Scene preparation is bounded by native budgets and at most 8192 scoped records; structure footprint definitions are cached for at most 4096 prefab hashes. Scope gaps or unsupported oversized modified pieces remain shared observation limitations. Native sapling space checks continue after planting; the configured structure buffer is evaluated when renewal places the sapling and does not remove an existing tree or continuously enforce a future no-tree zone.

## Structure processing bounds

Cache piece classification, local collision bounds and default scale for at most 4096 prefab definitions. Before transforming all eight footprint corners, reject known geometry whose conservative pivot-centred bound cannot reach the configured clearance. Offset, replicated scale, rotation and height-separated structures remain covered. Unknown geometry/definitions still defer renewal; no distance-only guess bypasses an unknown footprint.

## Player-service integration

Follow the [required feature hookup](../architecture.md#required-feature-hookup). Plugin injects its existing PlayerServices. The module owns one presence subscription and at most one controller per world. Enablement, exact game compatibility, dedicated-server world readiness and joined-world presence gate gameplay independently. False or unknown presence disposes the controller before acknowledging pause; reconnect creates a fresh controller. World replacement disposes old resources. No activity lease or AFK inference is needed. Ready is reported once independently of presence. There is no independent empty-server gameplay responsibility.

## Logging

Unknown structure context identifies the blocking object/prefab and whether its definition, collision geometry, scale or transform is unavailable. Repeated identical blockers combine across affected stump IDs, with at most one reminder per five minutes within the existing decision budget. The diagnostic identity cache holds at most 4096 entries. Main-thread stage timing also separates scope refresh and structure exclusions, so terrain and disk work are not assumed to explain all processing cost.

Use the [shared logging and suppression policy](../architecture.md#logging). Enabled/Disabled, Ready and failures remain visible independently of DebugMode. Each completed processing pass combines confirmed results into one Info count; empty passes are silent. Optional changed-result diagnostics have a single summary per 60 seconds, with pass and lifetime counts. Sample at most 16 decision records per minute with source identity and placement/exclusion reason. Pending state clears on controller disposal, except the durable ForestRenewal ledger. The effective global-or-feature policy and hidden suppression apply before optional formatting.

## Acceptance criteria

Each accepted stump ID has one persisted chance decision and at most one placement attempt across standing/removal triggers. Known standing stumps can enter renewal; missing/unloaded stumps alone create no records or destruction confirmations. Building during a pending delay prevents renewal inside the configured footprint clearance. Removing a tracked stump preserves its existing decision and timer. Standing-stump conversion removes its source without chopping loot before placing the sapling. Exact native sapling mappings, all configured exclusions and the persisted location cooldown govern every placement; native growth properties remain unmodified. Pending decisions survive restart without rerolling or replaying consumed decisions.

## Compatibility and shared criteria

Use the [supported environment](../server-setup.md#supported-environment) and shared exact-version guard. Each module isolates failure and releases only its own resources. Disabled features bind configuration but install no gameplay hooks and scan nothing. Objects outside verified scope retain native behavior. Acceptance requires independent enablement, repeatable cleanup, native state preservation, bounded retained state and the ownership/persistence rules below. Shared observation and delivery qualifications belong in [limitations](../limitations.md#new-world-features).

Debug ledger-write timing reports background I/O duration separately, at most once per minute. Main-thread snapshot serialization, terrain preparation and world mutation each report their own bounded average/maximum timing once per minute. It is not gameplay-thread processing time.

Optional controller-pass timing reports duration_avg_ms and duration_max_ms at most once per minute for nonempty scope. Collection follows effective debug policy and includes synchronous controller processing only; see [shared measurement limitations](../limitations.md).
