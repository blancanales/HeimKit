# HeimDefender

## Behavior and hosting

HeimDefender runs on the world host in solo, Start Server and dedicated play. Enabled defaults on and FreeWoodBolts defaults off. Eligible objects are persistent player-built piece_turret records with a nonzero creator. A vanilla or console client can own the simulation. Native trophy filters, aiming, cooldown, permissions, damage and projectile collisions remain in effect.

The owner uses Turret.UpdateTarget and UpdateAttack. The host writes native HasFields, HasFieldsTurret and the three boolean overrides Turret.m_targetPlayers, Turret.m_targetTamed and Turret.m_targetTamedConfig. ZNetView.LoadFields reads these from the replicated record on instantiation. Existing host instances reload from the prefab defaults and the current record. The familiar and trophy-filtered paths both exclude players and tames. The [SmartDefense turret processor](https://github.com/ArgusMagnus/ValheimServersideQoL/blob/5c4abf661cce564d5563495c6106ea493ec8d4b2/ServersideQoL.SmartDefense/TurretProcessor.cs) uses the same native field mechanism.

With FreeWoodBolts enabled, the host may top up a player-built Ballista with the selected bolts. The host or an authorized admin selects BoltsPerReload through the existing bounded numeric settings path (integer 1 to 40, default 40). Each fill uses the smaller of that value and the effective positive magazine capacity. The delay is the native shot cooldown multiplied by one less than the target stock, with a minimum of one cooldown. Recheck authoritative stock before writing. At each eligible interval add the deficit in one write. At or above the target, leave stock intact and schedule the next check. Preserve a different loaded ammunition type until it runs out. Live setting changes affect the next batch. Switching off free bolts stops future refills. Native firing consumes each bolt and the ordinary hover display shows the remaining stock.

The refill operates on the native ammo type and count under confirmed ownership, rechecking current stock, capacity and server settings before writing. Track the refill deadline per world and Ballista across ownership changes and area reloads. Use the existing bounded nearby-piece discovery. Restore native magazine fields by removing the previous unlimited-ammo overrides on records marked by HeimKit, preserving unrelated overrides and existing stock. Debug samples identify the Ballista, prior and updated stock, ammo type, effective capacity, refill interval and the reason for a deferred refill. Stock-only updates use native replication and preserve the target. On its first native ownership handoff, an eligible saved record with zero data and owner revisions receives its initial data revision before the owner simulates it. This host replication step also prepares records for later live enablement. A zero revision permits starting a static lease, and an existing remote owner must still return its state and ordering acknowledgement before any refill.

The Bolt type dropdown appears immediately to the right of Free bolts in F7 Server Settings. It offers Wooden (default), Black Metal, Flametal and Bloodgold. Persist one choice per host and retain the existing FreeWoodBolts enable setting for compatibility. Changing type takes effect once the previous stock runs out. The host maps the choice to an allowlisted native ammo prefab and validates it against the Ballista before loading. Use the existing host/admin settings permissions and report the actual ammo type in refill diagnostics. Vanilla guests receive the selected ammunition through ordinary replicated magazine state. While HeimDefender and Free bolts are both enabled, the host reserves automatic Ballista loading for HeimDefender. See the [StationSupply intake rules](station-supply.md).

## Player-service integration and authority

GameplayModules registers the module. The controller requires a compatible world, native services and joined presence. It leases a targeted Core candidate subscription and advances discovery in slices of sixteen units or one millisecond. It releases the controller, subscriptions and leases on pause or shutdown. A world-scoped flag records that changes may need restoration when the module is disabled. Previously managed worlds continue looking for nearby originals to restore while occupied. Worlds that have never enabled HeimDefender do no restoration scans. No AFK activity lease is needed.

HeimDefenderBallistaPolicy preserves the prior presence and values of the targeting fields on each original record. The controller reconciles one Ballista at a time. Core ObjectTransferAuthority drains an active remote owner's latest state and confirms the ordering barrier before host mutation. The host pauses its Ballista simulation during the transaction, refreshes nearby recipients through the shared same-ID cache refresh and resumes native ownership distribution. Lost ownership, invalid identity, native interactions or timeout end the transaction. Reconciliation rechecks current settings after the drain. Other turret prefabs and world-created pieces are outside its scope.

Players use ordinary Valheim interactions. HeimDefender registers no guest request to choose targets, issue shots, create ammunition or change server policy. Server settings use the existing host/admin permission checks. Target diagnostics accept an observed remote target only when its physical sender matches the routed sender and the Ballista owner.

## Diagnostics

The host records enablement and completed policy applications at Info. Bounded Debug samples identify policy changes, prior owner, record revision, free mode, stock, refresh recipients and ordering results. Target observations include world, Ballista, owner and target IDs, prefab, faction, tame and aggravation state, and trophy count. A loaded local player and target also permit comparison with native BaseAI.IsEnemy. Owner-reported target selections during combat use the bounded observation stream. No process scans for creatures for diagnostic purposes.

An optional client trace observes the native target RPC, records owner or observer role, the three live filter values, capacity and ammo type. A vanilla guest requires no trace or plugin. See [gameplay and evidence limits](../limitations.md#heimdefender).
